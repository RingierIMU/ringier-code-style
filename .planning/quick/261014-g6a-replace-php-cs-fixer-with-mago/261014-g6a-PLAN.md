<interfaces>
Mago wrapper API at 1.57.0. Source: composer/src/internal.php, namespace Mago\Internal, autoloaded via composer "files". Its own runner, composer/bin/mago, calls them in this order:
- get_version(): string. Reads Composer\InstalledVersions::getPrettyVersion('carthage-software/mago') and throws RuntimeException if null.
- detect_architecture(): string. Returns x86_64|aarch64|armv7|arm and throws RuntimeException otherwise.
- detect_platform(string $architecture): array{os, vendor, suffix, extension}. Throws RuntimeException.
- build_target_triple(string $arch, string $vendor, string $os, string $suffix): string
- get_archive_extension(string $os, string $suffix): string. Returns ".zip" or ".tar.gz".
- ensure_binary(string $version, string $triple, string $executableExtension, string $archiveExtension, string $binDir): string. Returns "{binDir}/{version}/mago-{version}-{triple}/mago{ext}". It downloads from github.com releases only if that path is missing, mkdirs recursively, and takes a per-version+triple flock.
- ensure_schema(...) writes schema.json into the package dir. Do NOT call it. That dir is read-only inside the PHAR, and the schema only matters to editors.

Mago CLI behaviour, confirmed in src/config/mod.rs and src/commands/format.rs at 1.57.0:
- `mago --config <file> fmt [PATH]...`. Explicit paths override the `[source]` config. The workspace defaults to cwd.
- With `--config <file>`, mago detects the config format from the file EXTENSION and rejects an unrecognised one. A bare tempnam() path (no `.toml`) is therefore rejected, so the temp copy must end in `.toml`.
- `mago fmt --stdin-input` writes the formatted code to stdout. On a parse error it writes NOTHING to stdout and exits non-zero.
</interfaces>
