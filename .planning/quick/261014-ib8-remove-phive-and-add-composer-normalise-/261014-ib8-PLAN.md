Design (settled at planning time, verified against package source; do not re-derive):
- Host the command in-process, mirroring ergebnis' own PHAR entry `phar/composer-normalize.php` at tag 2.54.0. It builds a `NormalizeCommand` from `new Factory()`, a `ComposerJsonNormalizer` with the schema path, `new Printer()` and a `Differ` over `StrictUnifiedDiffOutputBuilder` with fromFile `original` and toFile `normalized`. It adds that command to `new Composer\Console\Application()` and runs `normalize`.
- `composer/composer` must be required explicitly. The plugin only requires the virtual `composer-plugin-api`/`composer-runtime-api`. `NormalizeCommand` extends `Composer\Command\BaseCommand`, and its `getIO()` returns a NullIO (no output at all) unless the host app is `Composer\Console\Application`.
- Do NOT use `NormalizePlugin::getCommands()`. It wraps the schema path in `realpath()`, which returns false for a `phar://` path. `resource/schema.json` ships in the dist (it is not export-ignored).
- The trap that drives the path handling: the PHAR stub calls `Phar::interceptFileFuncs()` (box.json `intercept: true`), and the PHAR root contains this repo's own composer.json and composer.lock (checked by listing builds/ringier-code-style). Code running from inside the PHAR that reads a relative path gets the bundled file when one exists at that path. RunsMago.php documents the same trap for mago.toml. If the consumer's lock exists, `NormalizeCommand` runs a nested `new Application()` with `update --lock --working-dir=<dir of file>`. That nested run reads `Factory::getComposerFile()`, which is env `COMPOSER` or the relative `./composer.json`. So the absolute path must go into env `COMPOSER` through `Composer\Util\Platform::putEnv`. That call sets putenv, `$_SERVER` and `$_ENV`, and `Platform::getEnv` reads `$_SERVER` first.
- Composer's `Application::doRun` loads consumer plugin commands only for unknown, list or help commands, so registering `normalize` up front skips that. Consumer plugins still load inside `Factory::createComposer`, the same as the old PHAR. doRun sets non-interactive when stdin is not a TTY, and it chdirs back after `--working-dir`, so `runMago()`'s `getcwd()` stays correct.
- symfony/console is locked at v7.4.17. composer/composer 2.10.3 accepts ^7.1.10 || ^8.0. Symfony 7.4 deprecates `Application::add()`, so use `addCommand()`.
- Baseline measured with the current phive PHAR in a scratch project with `{"require": {"ext-json": "*", "php": ">=8.3"}, "name": "acme/scratch", ...}` and a lock from `composer update --no-install`. `fix` moved `php` above `ext-json`, rewrote content-hash, and `composer validate` then exited 0. A stale lock makes `composer validate` exit 2. The run needs no packages from the network.
- The current PHAR holds 2 root `tools/` entries. vendor/jolicode/* contains nested `tools/` dirs, so the no-tools check matches the root prefix only.
- `./ringier-code-style app:build <name>` writes builds/<name>, restores config/app.php and box.json itself, and leaves builds/ringier-code-style untouched when `<name>` differs.
- No test runner is installed (vendor/bin has no pest). The scratch-project end-to-end commands below are the checks.
